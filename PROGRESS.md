## Pre-Phase-3 findings (environment)
- **No pretrained weights available offline.** Only `resnet18-f37072fd.pth` is cached; no EfficientNet or
  YOLOv8 weights. The rule is "do not download anything else", so **EfficientNet-B0 and YOLOv8n are
  trained from scratch** (`classifier.pretrained: false`, `detector.model: yolov8n.yaml`).
  This is expected to cost accuracy compared with ImageNet/COCO initialisation.
- Ultralytics download and telemetry side effects were found and disabled in
  `src/detect/yolo_utils.py::ultralytics_offline`: analytics sync off, AMP self-check (which downloads
  `yolo11n.pt`) skipped, `check_font` (which downloads Arial.ttf, because the case-sensitive lookup misses Windows
  `arial.ttf`) skipped, `YOLO_OFFLINE=1`, `YOLO_AUTOINSTALL=0`, and any remaining download raises an
  error. Verified: `YOLO('yolov8n.pt')` -> "download blocked by project policy".
- Classifier speed: a 1-epoch smoke run took 74 s; a micro-benchmark showed the model step alone is
  about 14 s/epoch (cuDNN deterministic is not slower here; `channels_last` was 6x slower, so not used).
  Real epochs then ran at about 28-34 s while the CPU was shared with frame generation.

## Phase 3: preprocessing
- `src/preprocess/enhance.py`: illumination correction (`border_median` subtract for crops,
  `gaussian_subtract` for frames; dark-field background is near-black, so we subtract, never
  divide), NL-means denoise (h=5), CLAHE on L channel with tile grid adapted to image size.
  8 unit tests (`tests/test_preprocess.py`).
- `python -m scripts.compare_preprocess` -> `results/preprocess_comparison.png` (train crops).
  Observation: changes are subtle. The ZooLake crops were already enhanced by the camera software
  (SPCConvert), and CLAHE lifts the crop background slightly above the black letterbox padding,
  so the crop rectangle becomes faintly visible.
- The same `prepare_crop` (`src/classify/data.py`) is used in training and in the pipeline.
- Ablation (25 epochs each, unweighted loss, VAL macro F1 decides):
  - `python -m scripts.train_classifier --name abl_pre0 --use-preprocess 0 --weighting none --epochs 25`
  - `python -m scripts.train_classifier --name abl_pre1 --use-preprocess 1 --weighting none --epochs 25`
  - Result (`results/ablation.csv`, VAL): without preprocessing macro F1 0.8608 (organisms 0.9161, acc 0.9115);
    with preprocessing 0.8621 (organisms 0.9223, acc 0.9149). Best epoch 23 of 25 in both runs.
  - **Decision:** preprocessing ON (the decision rule set beforehand: higher val macro F1). **Honest reading:** a +0.0013
    difference is well within single-seed noise (val macro F1 moved by more than 0.05 between adjacent
    epochs), so preprocessing neither clearly helps nor hurts here.

## Phase 4: classifier
- EfficientNet-B0 (timm, from scratch), letterbox 128 px, GPU batch augmentation (flips, rotation
  up to 180 degrees, scale 0.9-1.1, brightness/contrast 0.15), AdamW, cosine schedule with warmup, label smoothing 0.1,
  AMP, checkpoint every epoch (`last.pt`, resumable), best by val macro F1, early stop patience 10.
- Weighting experiment (40 epochs each, preprocessing on):
  - `python -m scripts.train_classifier --name cls_w0 --weighting none`
  - `python -m scripts.train_classifier --name cls_w1 --weighting inverse_sqrt_freq`
  - Result (VAL, `results/ablation.csv`): unweighted macro F1 0.9055 (organisms 0.9576, acc 0.9518);
    inverse-sqrt weighted 0.9051 (organisms 0.9549, acc 0.9469). Both best at epoch 37 of 40.
    Epochs after the first took about 17 s (the first epoch about 70 s: CUDA/cuDNN start-up).
  - **Decision:** unweighted (`python -m scripts.select_classifier --prefix cls_` ->
    `results/classifier_selection.json`, `models/classifier_best.pt`). The gap is noise, consistent with the
    ZooLake paper's finding that reweighting does not help. Weak spot: `reject` val F1 0.541 (w0) / 0.556 (w1),
    while every organism class is at 0.92 or above.
  - Note: the best epoch was 37 of 40, so the model may still have been improving slightly. 40 epochs kept each run
    at about 12 min, well inside the 45-min budget; not extended, to avoid tuning more on val.
- Uncertainty threshold (`python -m scripts.choose_threshold`, VAL only): 0.59 -> val coverage 0.9528,
  accepted accuracy 0.9701 (target 0.97). `results/thresholds.json`, `results/uncertainty_curve.png`.
